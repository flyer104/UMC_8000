# UMC-8000

**一台 8 位教学型处理器**：Verilog 实现，能仿真、能综合、能跑通一条完整的程序。

UMC-8000 属于 **UMC（usual micro computer）工程实践课题**，是该项目 8 位机的第一块基石。
它的目标不是性能，而是**可解释性** —— 让 CPU 里的每一个信号都能被看见、被解释。

> 直接上手 RISC-V，你要先面对流水线、乱序执行、分支预测、多级 Cache、
> 完整 RV32I 指令集和特权级规范。台阶太高。
>
> UMC-8000 换个方向：位宽降到 8 位，指令降到 4 条，模块降到 3 个。

---

## 规格

| 项目 | 值 |
| --- | --- |
| 数据宽度 | 8 bit |
| 地址宽度 | 6 bit（可寻址 64 个内存单元） |
| 指令宽度 | 8 bit 定长 |
| 指令条数 | 4 |
| 寄存器 | 1 个 8 位累加器 `ACC` |
| 执行模型 | 单周期，顺序执行，无流水线 |
| 顶层模块 | `UMC_8000` |
| RTL 规模 | 7 个源文件 |

## 架构

```
        ┌──────────────────────────────────────────┐
        │           内存 / 指令存储器（外置）        │
        └───────┬───────────────────────▲──────────┘
      mem_rdata │              mem_wdata / mem_addr / mem_write
                ▼                       │
   ┌────────────────────┐   ┌───────────┴────────────┐
   │      控制器         │   │        数据通路         │
   │   controller.v     │──▶│      datapath.v        │
   │  取指 → 切分 → 译码  │   │  累加器 · 加法器        │
   └────────────────────┘   │  2 × mux · 2 × demux   │
                │            └────────────────────────┘
        is_end  │
                ▼
   ┌────────────────────┐
   │    程序计数器 PC     │
   │       pc.v         │
   └────────────────────┘
```

**控制与数据分离**：控制器只看指令、产生控制信号；数据通路不懂指令，
只被控制线指挥。两者之间**只有 4 根控制线**（`mem_in`、`sum_in`、
`sum_out`、`sum_en`），加上 `is_end` 和 `mem_write` 就是全部接口。

## 指令集

一条指令 8 位：**高 6 位是内存地址，低 2 位是操作码**。

```
 bit   7  6  5  4  3  2 │ 1  0
      └──── 地址 n ────┘ └opcode┘
```

| 汇编 | opcode | 语义 | 说明 |
| --- | --- | --- | --- |
| `load n` | `00` | `ACC ← M[n]` | 把内存地址 n 的值读进累加器 |
| `store n` | `01` | `M[n] ← ACC` | 把累加器的值写回内存地址 n |
| `add n` | `10` | `ACC ← ACC + M[n]` | 累加器与地址 n 的值相加 |
| `rot` | `11` | 停机 | PC 停止递增，程序结束 |

译码不需要查表，也不需要微码 ROM：

```verilog
assign mem_addr = instru[7:2];   // 地址直接就是高 6 位
assign opcode   = instru[1:0];   // 操作码直接就是低 2 位
```

机器码算法：

```
机器码 = (n << 2) | opcode
```

## 完整的 1 + 1 示例

这个例子包含两部分：**先在内存里放好两个 1**，然后由程序把它们相加。

### 第一步：初始化内存

在内存地址 `0x0` 和 `0x1` 各放一个 `1`：

| 地址 | 值 | 说明 |
| --- | --- | --- |
| `0x0` | `0x01` | 第一个加数 |
| `0x1` | `0x01` | 第二个加数 |

在测试平台里的写法（`tb/global_tb.v`）：

```verilog
initial begin
    ram[0] <= 1;      // M[0] = 1
    ram[1] <= 1;      // M[1] = 1
end
```

### 第二步：程序

把这两个 1 相加，结果存到 **`0x3`**：

| 指令地址 | 汇编 | 机器码 | 计算过程 | 含义 |
| --- | --- | --- | --- | --- |
| `0x0` | `load 00` | `0x00` | `000000 00` | ACC ← M[0] |
| `0x1` | `add 01` | `0x06` | `000001 10` | ACC ← ACC + M[1] |
| `0x2` | `store 03` | `0x0D` | `000011 01` | M[3] ← ACC |
| `0x3` | `rot` | `0x03` | `000000 11` | 停机 |

在测试平台里的写法：

```verilog
initial begin
    rom[0] <= 'h00;   // load  00
    rom[1] <= 'h06;   // add   01
    rom[2] <= 'h0d;   // store 03   <- 结果写入 M[3]
    rom[3] <= 'h03;   // rot
end
```

> **注意是 `0x0D` 而不是 `0x09`。**
> `store 03` 的地址字段是 3（`000011`），操作码是 `01`，
> 拼起来 `00001101` = `0x0D`。
> 如果想存到 `0x2`，那才是 `store 02` = `00001001` = `0x09`。

### 第三步：执行结果

| 拍 | `pc` | `instru` | `mem_addr` | `mem_write` | `ACC` | 内存变化 |
| --- | --- | --- | --- | --- | --- | --- |
| 复位 | 0 | — | — | 0 | 0 | — |
| 1 | 0 | `0x00` | 0 | 0 | 0 → **1** | — |
| 2 | 1 | `0x06` | 1 | 0 | 1 → **2** | — |
| 3 | 2 | `0x0D` | **3** | **1** | 2 | **M[3] ← 2** |
| 4 | 3 | `0x03` | 0 | 0 | 2 | — （`is_end` 拉高） |
| 5+ | **3** | `0x03` | 0 | 0 | 2 | **PC 冻结** |

**最终结果**：

| 位置 | 值 |
| --- | --- |
| `ACC` | `2` |
| `M[3]` | **`2`** ← 结果在这里 |
| `M[0]` | `1`（未改动） |
| `M[1]` | `1`（未改动） |
| `M[2]` | `0`（本程序没有写它） |

**两个决定性的检查点**：

1. `pc` 必须停在 **3**，不再增长
2. `M[3]` 最终必须等于 **2**

```

├── core/                  RTL 源码
│   ├── UMC-8000.v         顶层，把三个模块接起来

│   ├── datapath.v         累加器 / 加法器 / mux / demux
│   ├── pc.v               程序计数器，含停机锁存
│   └── mod/               最小单元
│       ├── adder.v        8 位加法器
│       ├── mux.v          mux 与 demux
│       └── reg.v          8 位带使能寄存器（累加器）
├── tb/                    仿真测试平台
│   ├── global_tb.v        整机：CPU + RAM + 指令 ROM  ← 1+1 示例在这里
│   ├── comp_tb.v          控制器 + 数据通路 联调
│   ├── controller_tb.v    控制器单独测试
│   ├── datapath_tb.v      数据通路单独测试
│   ├── pc_tb.v            PC 单独测试
│   └── vcd/               参考波形
├── *_tb.sh                各测试的编译 + 运行脚本
├── synth.ys               Yosys 综合脚本
├── UMC_8000_synth.v       综合后的门级网表
└── report.log             综合报告
```

## 快速开始

### 工具链

| 工具 | 用途 | 必需 |
| --- | --- | --- |
| Icarus Verilog（`iverilog` / `vvp`） | 编译并运行仿真 | 是 |
| GTKWave | 查看波形 | 建议 |
| Yosys | 综合 | 否 |

```bash
# Ubuntu / Debian
sudo apt install iverilog gtkwave yosys

# macOS
brew install icarus-verilog gtkwave yosys

# Windows
#   Icarus Verilog  http://bleyer.org/icarus/
#   OSS CAD Suite   https://github.com/YosysHQ/oss-cad-suite-build/releases
```

### 跑仿真

```bash
cd rtl

bash global_tb.sh       # 整机跑 1+1 程序（最重要）
bash comp_tb.sh         # 控制器 + 数据通路
bash controller_tb.sh   # 只看译码
bash datapath_tb.sh     # 只看数据通路
bash pc_tb.sh           # 只看 PC 与停机
```

看到 `global similation is over-----------------` 即完成。
波形写在 `tb/vcd/` 下。

> Windows 下脚本里的 `rm` 需要 bash 环境，请用 **Git Bash** 或 **WSL** 运行；
> 也可以手动执行脚本里那两行 `iverilog` / `vvp` 命令。

### 看波形

```bash
gtkwave tb/vcd/global_tb.vcd
```

建议按这个顺序拖入信号：`clk` → `rst` → `pc` → `instru` → `mem_addr`
→ `mem_write` → `is_end` → `UMC_8000.u_datapath.sum_output`（累加器）。

### 综合：生成网表

```bash
cd rtl
yosys -l report.log -s synth.ys
```

| 参数 | 作用 |
| --- | --- |
| `-s synth.ys` | 执行综合脚本 |
| `-l report.log` | 把完整的综合日志写入 `report.log` |

**输出**：

| 文件 | 内容 |
| --- | --- |
| `UMC_8000_synth.v` | 综合后的门级网表（由 `synth.ys` 里的 `write_verilog` 生成） |
| `report.log` | 综合日志：读入的模块、优化过程、`stat` 统计、`check` 结果、警告 |

综合完成后建议先看日志里有没有警告：

```bash
grep -i "warning\|error" report.log
```

**本项目的目标状态是零告警。** 出现告警时按
[学习手册第 8 节](doc/学习手册.md#8-编码与测试约定) 的约定逐条核对。

`synth.ys` 使用的是 Yosys 的**通用门级映射**（`proc` / `opt` / `fsm` /
`memory` / `techmap`），**没有绑定具体工艺库**，目的是让你看清逻辑被
综合成了什么，而不是给出某个工艺下的面积和功耗数字。

想拿到真实的门数和面积，需要额外的两步和一份 `.lib` 工艺库文件：

```tcl
dfflibmap -liberty /path/to/your.lib
abc -liberty /path/to/your.lib
```

## 设计要点

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 控制方式 | 硬布线 | 4 条指令不值得引入微码 ROM |
| 寄存器组织 | 累加器 | 避免寄存器堆的编号译码与 RAW 冲突 |
| 执行模式 | 单周期 | 避免冒险处理与转发逻辑 |
| 指令格式 | 8 位定长 | 避免变长指令的对齐状态机 |
| 停机实现 | 状态锁存（`halt` 寄存器） | `is_end` 是电平信号，必须锁存而不是每拍翻转 |
| 存储器 | 外置端口 | CPU 边界清晰，内存模型可替换 |

---

## 设计约束与取舍

- **停机**：`pc.v` 用 `halt` 寄存器锁存停机状态。
  `is_end` 是控制器的组合逻辑输出，只要 PC 停在 `rot` 上就一直是高电平，
  因此不能用边沿器件响应，否则会在每个时钟沿反复翻转。
- **`rot` 之后不可恢复**：没有中断，只能靠复位。
- **无符号运算**：`add` 溢出直接按 8 位回绕，不产生任何标志位。
- **指令与数据同存**（冯·诺依曼结构）：指令放在 `M[0..3]`，
  数据放在 `M[0]`/`M[1]`/`M[3]` —— 两者共用同一块内存，
  注意别让 `store` 覆盖掉还没执行的指令。
- **`pc` 宽 8 位、地址宽 6 位**：`pc` 留了 2 位余量，便于以后扩内存。
